Operator setup

For platform operators only. Customer end-users do not need this.

Private template

Set AI Change Platform env:

SF_TEMPLATE_REPO=<github-user-or-org>/serviceflow-whitelabel-template

Default used by ServiceFlow deploy scripts: Elijah23Johnson/serviceflow-whitelabel-template.

GCP

  • Project: streaminglive-633c1 (not aspen-flight-ops).
  • Mount deploy SA on ACP as WL_GCP_SA_KEY / GCP_SA_KEY so provision copies GCP_SA_KEY onto each tenant repo.
  • Mount WL_GCP_PROJECT_ID / GCP_PROJECT_ID the same way.

Checklist

  1. Mark the private template as a GitHub Template repository.
  2. Push master and develop (keep deploy workflow names).
  3. Install ACP + Cursor GitHub Apps (prefer All repositories).
  4. Provide ACP_GITHUB_HOST_TOKEN (classic PAT with repo + workflow) — App installation tokens cannot clone private templates via generate.
  5. Share ACP_HANDOFF_SECRET and ACP_INTERNAL_SECRET with the main ServiceFlow API.
  6. On activate: generate repo, invite collaborators, sync secrets/vars, begin domain connect.

Customer activate path

  1. Admin grants White-label AI Change.
  2. Set apex + collaborator emails → Activate.
  3. Verify domain ownership for Cloud Run mapping.
  4. Wait for first real Deploy after secrets land.
  5. Open AI Change Studio or Download / Open ServiceFlow Pro IDE.

Sync note

GitHub templates do not auto-update generated repos. Re-sync curated app code via the platform sync script. Prefer sync into tenant develop.
